# MoguCupDX

maimai の非公式大会「もぐらたたきカップ」の運営ツールです（非公式・ファンメイド）。

- `index.html` … 参加者ページ
  - ユーザー登録・ログイン（2fRATE のランキングに登録している人は、2fRATE のユーザー名と PIN でそのままログインできる）
  - 参加申請（エントリー名・X の ID・maimai のレート・2fRATE）
  - 自分の試合の確認と、自選曲3曲の提出（2fRATE の計算ページと同じ形の楽曲一覧から選ぶ。試合の上限を超える譜面と運営課題曲は出ない）
  - BAN（相手の自選曲から1曲）と、残った2曲からの自選曲の決定
- `admin.html` … 運営ページ（管理者用の鍵で保護）
  - 参加者の一覧・編集・削除・CSV 書き出し、このツールで作ったユーザーの仮PIN発行
  - 大会設定（受付・締切・お知らせ、いまの段階、新しい対戦カードの既定の上限と課題曲）
  - 組み合わせ（2fRATE 順・ランダム・手動）、試合ごとの上限（譜面定数）と運営課題曲、提出状況の確認と代理入力
  - 告知画像（組み合わせ発表／選曲公開／BAN結果・対戦曲）を PNG で保存
- `worker/` … Cloudflare Workers + D1 の API

## デモ

`demo.html` から、参加者ページ・運営ページを本番と同じ動きで試せます（`index.html?demo=1`、`admin.html?demo=1` でも可）。
本物の `worker/worker.js` を、ブラウザの中のデータベース（`demo/memdb.js`）につないで動かすので、サーバーには何も送りません。
データはそのブラウザの localStorage にだけ保存され、画面下の操作バーから参加者の切り替え・段階の切り替え・ほかの参加者の自動入力・リセットができます。

## 申請の設問と部門

参加申請では Q1〜Q13（X の ID、Discord 名、スコアタで使用する名前、部門、レート、2fRATE、神プレート、部門別の質問）を集めます。
部門は「らいむ部門」「れもん部門」で、両方に申請した人は部門ごとに1試合ずつ持ちます。
組み合わせ・上限・運営課題曲・告知画像は部門ごとに分かれます。

らいむ部門で両者が Q11（Lv14）に「はい」と答えた試合は、自動で Lv14 解禁になります（運営が試合ごとに切り替えも可）。
解禁された試合では、上限を超えるレベル14（定数 14.0〜14.5）を1曲まで自選曲に含められます。

## 大会の形式と対戦曲

運営ページの「大会設定」→「大会の形式」で選びます。

| 形式 | 対戦曲 |
|---|---|
| 本編 | 両者の自選曲＋運営課題曲。両者が同じ曲を自選曲にしたときだけ、その曲＋運営課題曲2曲 |
| mini | 両者の自選曲のみ（運営課題曲なし）。同じ曲なら1曲 |

運営課題曲2は試合ごとに設定し、参加者には両者の自選曲が同じになった試合でだけ、対戦曲確定の段階で表示されます。

## 段階の進め方

運営ページの「大会設定」→「いまの段階」を切り替えて「設定と組み合わせを保存」を押します。

| 段階 | 参加者ができること |
|---|---|
| 組み合わせ発表前 | 参加申請のみ（対戦カードは見えない） |
| 自選曲の提出 | 自分の試合を見て、自選曲を3曲提出（期間中は出し直せる） |
| BAN | 相手の自選曲が公開され、1曲を BAN |
| 自選曲の決定 | BAN されなかった2曲から1曲を決定 |
| 対戦曲確定 | 対戦する3曲を確認 |

## 設置手順

### v3 から v4 へ更新する場合（2fRATE の値の読み込み）

1. D1 のコンソールで `worker/migrate_v4.sql` を実行する
2. Worker のコードを新しい `worker/worker.js` に置き換えてデプロイする
3. 2fRATE の Worker の `check` の返事に、PIN が合っているときだけ `rateFull` と `counts`（star5Mas・star5Remas・star6Mas・star6Remas など）を入れる

### v2 を設置済みで、申請の設問を追加した版（v3）へ更新する場合

1. D1 のコンソールで `worker/migrate_v3.sql` を実行する
2. Worker のコードを新しい `worker/worker.js` に置き換えてデプロイする

### すでに初版を設置している場合（v2 への更新）

1. D1 のコンソールで `worker/migrate_v2.sql` を実行する（1行ずつでも可）
2. Worker のコードを新しい `worker/worker.js` に置き換えてデプロイする
3. Worker の「設定」→「バインディング」で「サービスバインディング」を追加し、変数名 `RATE2F`、サービスに 2fRATE の Worker を選ぶ
   （Worker から同じアカウントの別の Worker の URL へ直接送ると失敗することがあるため）
4. リポジトリのファイルをすべて新しいものに置き換える

### 1. Worker と D1 を作る

```sh
cd worker
npx wrangler login
npx wrangler d1 create mogucupdx          # 表示された database_id を wrangler.toml に書く
npx wrangler d1 execute mogucupdx --remote --file=schema.sql
npx wrangler secret put ADMIN_KEY         # 運営ページの鍵（長めのランダムな文字列）
npx wrangler deploy
```

`deploy` で表示された URL（例 `https://mogucupdx.<アカウント>.workers.dev/`）を `config.js` の `MOGU_API` に書きます。

Cloudflare のダッシュボードで作る場合は、Worker に `worker.js` を貼り付け、
D1 バインディング `DB`、シークレット `ADMIN_KEY`、変数 `ALLOWED_ORIGINS = https://n4f1316.github.io` を設定し、
D1 のコンソールで `schema.sql` を実行してください。2fRATE と連携するため、サービスバインディング `RATE2F`（2fRATE の Worker）も追加します。

### 2. GitHub Pages を有効にする

リポジトリの Settings → Pages で `main` ブランチの `/ (root)` を公開します。

- 参加者: `https://n4f1316.github.io/MoguCupDX/`
- 運営: `https://n4f1316.github.io/MoguCupDX/admin.html`

## メモ

- 1つのユーザーで申請できるのは1回だけです。同じエントリー名・同じ X の ID での二重申請も受け付けません（大文字小文字は区別しない）。
- PIN を5回続けて間違えると、そのユーザー名は15分ログインできなくなります。
- 2fRATE と連携しているユーザーの PIN は 2fRATE 側で管理します（仮PINは 2fRATE の運営ページで発行）。
- 締切は日本時間で判定します。締切を過ぎるか「参加申請を受け付ける」を外すと、申請できなくなります。
- 同名曲のジャケットは、種別（DX/ST）と難易度のレベルで1つに絞れたときだけ表示します。絞れないときは「?」になります。
